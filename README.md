# AURA — Automated Urban Response Analytics

## Pulse 109 · GovTech Camp 2026 · arbybyby

Платформа обработки обращений граждан для единого контакт-центра 109.

**Живая версия:** https://arbybyby.govtech-kz.com
**API-документация:** https://arbybyby.govtech-kz.com/docs

---

## Задача

В iKOMEK 109 поступает порядка 2,3 млн обращений в год, и поток продолжает
расти. Сейчас оператор читает каждое обращение, вручную определяет категорию
и выбирает ответственную службу. Ошибка маршрутизации означает недели
потерянного времени для заявителя, а городская авария становится заметной
только когда о ней доложат по инстанции.

AURA решает три вещи: классифицирует обращение, помогает оператору там, где
модель не уверена, и показывает руководству аномалии раньше сводок.

---

## Что работает

### Рабочее место оператора

Обращение приходит — категория, подкатегория, ответственная служба, приоритет
и адрес подставляются автоматически. Оператору остаётся подтвердить.

**Обработка низкой уверенности.** Когда сигнала мало — текст короче 20
символов, сработал единственный маркер, обращение на казахском из двух слов —
система не угадывает. Она помечает обращение как «Требует проверки» и
показывает три варианта категории с процентами, оставляя решение человеку.

**Обратная связь на дообучение.** Выбор оператора и любая ручная правка
категории сохраняются в набор коррекций (`store.CORRECTIONS`). Это размеченные
примеры «модель ошиблась вот так», готовые для следующего цикла обучения.

### Ситуационный центр

**Детектор всплесков.** Z-score по скользящему окну в 30 дней для каждой пары
«категория + регион». Отклонение выше двух сигм при абсолютном пороге в 4
обращения считается аномалией. Если истории меньше 7 дней — запасной путь по
простому порогу. Пример срабатывания: Астана, 19 обращений по ЖКХ при норме
3.6, отклонение 12.3σ.

**Прогноз нагрузки** на 1–3 месяца: линейный тренд методом наименьших
квадратов плюс недельная сезонность, снятая с данных, и доверительный интервал
по остаткам регрессии. Автоматически переключается на Facebook Prophet, если
библиотека установлена.

**Запрос к данным на естественном языке.** Правила разбора используют те же
маркеры, что и классификатор: «Сколько обращений по ЖКХ в Астане за неделю?»,
«Какой район лидирует по жалобам?».

**Выгрузка отчётов** в PDF (reportlab) и Excel (openpyxl) с листами «Сводка»,
«По регионам» и «Обращения».

## Данные

Собраны самостоятельно, а не взяты готовым файлом.

| Источник | Примеров | Что это |
|---|---:|---|
| dialog.egov.kz | 1425 | реальные обращения граждан, собраны своим скрапером |
| HuggingFace | 1957 | открытый датасет `Adilbai/kz-gov-complaints-data-kz-ru` |
| **Итого** | **3382** | 11 классов, 62% русский / 38% казахский |

**dialog.egov.kz** — официальная блог-платформа обращений к руководителям
госорганов, включая акимов. Скрапер (`data/scripts/scrape_dialog_egov.py`)
обходит поиск по 57 запросам на двух языках, соблюдает `Crawl-delay`, парсит
карточки по классам иконок (не зависит от языка интерфейса) и бинарным поиском
находит границу, за которой в выдаче начинаются обращения, а не публикации
ведомств.

**Обезличивание.** ФИО заявителя — структурное поле выдачи, оно не попадает в
выгрузку вообще. Текст дополнительно чистится: ФИО и инициалы → `[ЗАЯВИТЕЛЬ]`,
ИИН → `[ИИН]`, телефоны → `[ТЕЛЕФОН]`, почты → `[EMAIL]`. Проверка на
собранном корпусе: 0 совпадений по всем четырём шаблонам.

**Разметка** выводится из двух независимых источников — поискового запроса, по
которому обращение нашлось, и правил из `backend/services/classifier.py`. Где
источники согласны, метка принимается автоматически; расхождения идут на
ручную проверку.

Датасет HuggingFace машинно-сгенерированный, поэтому используется **только для
обучения** и исключён из валидации и теста: метрики ниже отражают работу
исключительно на живых обращениях граждан.

## Модель

**SetFit** — few-shot контрастное дообучение поверх мультиязычного энкодера.
Обучение на обычном ноутбучном CPU, без GPU.

| Вариант | Accuracy | F1 weighted | F1 macro | ru | kk |
|---|---:|---:|---:|---:|---:|
| Правила (baseline) | 0.349 | 0.483 | 0.452 | 0.376 | 0.255 |
| MiniLM-L12 | 0.538 | 0.534 | 0.467 | 0.521 | 0.596 |
| **multilingual-e5-small** | **0.538** | 0.533 | **0.528** | 0.545 | 0.511 |

Замер проведён на 212 реальных обращениях граждан. Синтетические данные в
тестовую выборку не допускались.

Модель обгоняет правила на **+54% относительно** по accuracy. На казахском
правила дают 0.255, модели — 0.51–0.60, то есть вдвое лучше. Выбран
e5-small: при равной общей точности у него выше F1 macro, то есть он ровнее
работает на редких классах («Лифт», «Светофоры»).

Разница между двумя энкодерами по языкам лежит в пределах статистической
погрешности: казахская часть теста — 47 примеров, стандартная ошибка ±7.3 п.п.
Выбор сделан по F1 macro, а не по случайному колебанию.

Обучение шло 3 итерации на CPU — выбран компромисс между временем и
качеством; прогон на 20 итерациях запускается той же командой.

## Архитектура

```
frontend/   React 18 + TypeScript + Tailwind + Recharts, сборка Vite
backend/    FastAPI, in-memory store (в проде PostgreSQL + pgvector)
data/       скрипты сбора, подготовки и обучения; датасеты; метрики
```

В продакшене FastAPI раздаёт API и собранную статику фронтенда одним процессом
на одном порту — организаторы выдают один порт, отдельный nginx не нужен.
Сервис живёт под systemd с автоперезапуском.

**Профиль ресурсов.** Приложение в проде занимает 30 МБ RAM и запускается на
любой машине. Инференс SetFit требует порядка 2 ГБ (torch + веса энкодера),
поэтому на демо-стенде классификация идёт по правилам, а модель разворачивается
отдельным сервисом там, где память есть. Веса лежат в S3, загрузка — одной
командой `s3_sync.py`. Такое разделение штатно для продакшена: веб-слой и
инференс масштабируются независимо.

### Ключевые модули бэкенда

| Файл | Что делает |
|---|---|
| `services/classifier.py` | классификация по правилам, определение низкой уверенности, варианты |
| `services/anomaly.py` | Z-score детектор всплесков по скользящему окну |
| `services/forecast.py` | прогноз нагрузки, Prophet или линейный тренд + сезонность |
| `services/nlq.py` | разбор вопросов на естественном языке |
| `services/embeddings.py` | поиск похожих обращений |
| `routes/exports.py` | генерация PDF и Excel |

### Скрипты данных

| Файл | Что делает |
|---|---|
| `scrape_dialog_egov.py` | сбор обращений с dialog.egov.kz + обезличивание |
| `download_hf_dataset.py` | загрузка открытого датасета с HuggingFace |
| `build_training_set.py` | черновая разметка из запроса и правил |
| `prepare_dataset.py` | склейка источников, дедупликация, стратифицированный сплит |
| `train_setfit.py` | обучение SetFit, метрики, матрица ошибок |
| `run_experiments.py` | последовательный перебор энкодеров |
| `s3_sync.py` | выгрузка датасетов, метрик и весов в S3 |

## Запуск

### Локально

```bash
# Backend
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# Frontend
cd frontend
npm install
npm run dev
```

Фронтенд на http://localhost:5173, API на http://localhost:8000.

### Скрипты данных и обучения

Отдельное окружение, чтобы не смешивать с зависимостями бэкенда:

```bash
python -m venv .venv-data
.venv-data/Scripts/activate        # Linux/macOS: source .venv-data/bin/activate
pip install -r data/scripts/requirements.txt

python data/scripts/prepare_dataset.py --real-eval
python data/scripts/train_setfit.py --num-iterations 20
```

### Docker

```bash
docker-compose up --build
```
